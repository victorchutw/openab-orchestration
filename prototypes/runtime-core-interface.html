拋棄式原型 — 不可作為正式產品

Runtime Core 的 seam 應該放在哪裡？

用三種截然不同的 caller interface 推動同一個 deterministic Run。三者刻意共用相同的狀態模型：這個原型要找出哪一種 interface 能把狀態轉移、授權、併發、稽核、完成判定與外部效果決策留在 Runtime Core 裡。

要回答的問題：Operator interface 是否只需陳述已獲授權的 Operator Action，而 Execution Adapter 是否只需回報觀察到的事實，並由 Runtime Core 獨自決定可持久保存的結果？

1. 選擇 interface 檢視方式

切換檢視方式不會重設 Run。請觀察同一個動作如何改變 caller request 與 receipt，而不改變權威行為。

建議 seam 所隱含的狀態所有權

Runtime Core 權威擁有

  • Run 生命週期、revision、Run Outcome，以及已接受的狀態轉移紀錄
  • Operator Action capability 與具冪等性的 receipt
  • Execution 帳冊與經驗證的 Execution Completion
  • 不可變 artifact 的身分、digest、歸屬，以及已接受的關聯
  • 可持久保存的外部效果意圖，以及效果為待處理、已觀察、不確定、已停止或已隔離
  • 依授權裁切的投影，包括每位 Reviewer 專屬的輸入 manifest

Caller 與 Adapter 僅可擁有

  • 可隨時丟棄的 UI 投影與呈現狀態
  • 傳輸連線、provider correlation 與 session 快取
  • Execution Adapter 背後的 workspace 運作機制
  • 執行或釐清外部效果時所需的 Adapter 本機紀錄
  • 絕不可擁有：Run Stage、Run Condition、Run Outcome，或自行宣告的 Execution Completion

2. 引導式否證

自由操作

所有按鈕都會保持可用。非法輸入必須在不改變狀態的前提下被拒絕；caller 不應為了維持 Runtime Core 安全而持有一份狀態轉移圖。

3. 權威 Run 投影

目前提供的 Operator Actions

尚未進行任何 exchange。
